# Planned work — features beyond V1

A backlog of features that the initial design missed or deferred, gathered
from the workbooks (what the Excel tool does or was reaching for), from how
hydrologists actually work, and from what a team running many catchments
needs. [roadmap/](./roadmap/README.md) holds the delivery plan, grouped into
four steps; this doc is the *what and why*, and each step plan says which
rows it delivers. Open work in detail is in [followups.md](./followups.md);
decisions and release blockers are GitHub issues.

**Status (2026-09-27):** the "Now" rows and most of "Next" are built: Step 2
(farmers, the published run, share links, alerts, data feeds, reports,
history, notes, Afrikaans) and the first slices of Step 3 (scenarios,
sweeps, applicants, allocations, yield, supply rules). The section headings
below are kept from the original plan.

Effort: **S** ≈ a day or two · **M** ≈ a week · **L** ≈ several weeks.
Status: ⬜ not started · 🚧 partly there · ✅ done · ❌ dropped.

**Fact-check (2026-09-30):** every client-facing row was checked against `main`, published hydrology and the law, not against the client's word or the workbooks. Rows now name their tracking issue; dropped rows say why.

## Suggested order

> **Superseded by [roadmap/](./roadmap/README.md)**, which groups these features into four steps by who they serve, with build plans. The order below is kept for history: items 1–2 are done, as are scenarios, run comparison, data feeds, forecast mode, alerts and reports (Phases A and B); instant preview and maps are not started.

1. Curtailment targets, EWR heat map, calibration window, export, help — the
   demo lands better with each (≈ 2 weeks).
2. Email (reset, verify, invites) and the change log — needed before real
   users (≈ 1–2 weeks).
3. Scenarios + run comparison + instant preview — the biggest jump in
   usefulness over the spreadsheet (≈ 3–4 weeks).
4. Data feeds + forecast mode + alerts — turns it into an operational tool
   (≈ 3–4 weeks), then maps and reports.

All of it is subject to the client's answers in
[plan.md § Questions for the client](./plan.md#questions-for-the-client).
